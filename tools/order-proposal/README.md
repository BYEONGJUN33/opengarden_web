# 주문형 제안서 (고객 카톡방용 링크)

고객에게 보내는 제안서를 **수량을 넣어 바로 견적을 요청할 수 있는 모바일 페이지**로 만든다.
2026-10-29 사용자 승인으로 도입.

## 흐름

```
고객: 카톡방 링크 열기 → 품목별 수량(구) 입력 → 합계 확인 → 연락처·동의 → [요청 보내기]
  → POST /api/quote (기존 견적 접수 API, 수정 없음)
  → 에어테이블 '견적요청' 레코드 생성 (요청번호 Q-YYYYMMDD-XXX)
  → 에어테이블 자동화 '카톡알림 · 웹 견적 신청' → Make '오픈가든 카톡 알림' → 대표 번호로 카톡
```

- 품목요약에 단가·금액이 들어간다: `1. 알리움 퍼플 센세이션 @₩500 = ₩150,000 · 12/14 · 300개`
- 요청사항(memo)에 제안서 ID·합계·최소주문 미달 여부·고객 메모가 들어간다.
- 품목JSON의 sku는 `<제안서ID>:<품종키>|<규격>` 형식 — 어느 제안서에서 온 요청인지 구분된다.

## 원칙 예외 (CLAUDE.md 절대 원칙 1·3)

이 페이지는 **고객별로 보내는 제안서**라서 가격·재고가 정적 HTML에 들어간다.
대신 아래를 지킨다.

- 주소는 `/p/<무작위 ID>/` — 추측할 수 없는 ID, 링크를 받은 고객만 연다.
- `<meta name="robots" content="noindex, nofollow">` + `robots.txt`의 `Disallow: /p/`.
- 사이트 메뉴·사이트맵·카탈로그 어디에서도 링크하지 않는다.
- 카탈로그 API(`api/catalog.js`)의 가격 화이트리스트는 그대로다. 이 기능은 API를 건드리지 않는다.

## 새 제안서 만들기

1. `proposals/<ID>.json` 작성 (기존 파일 복사 후 수정). ID는 `용도-날짜-무작위6자` 예: `air-20261028-3ebf85`.
   - `items[].rows` = `[규격, 재고, 단가]` — 재고는 숫자(입력 상한) 또는 `"10,000+"` 같은 문자열(상한 없음)
   - `minOrder` 0이면 최소주문 진행바를 숨긴다.
   - `mark`: `req`(★ 요청 품종) / `alt`(◇ 대체 제안, `alt`에 문구) / 빈칸
2. 사진을 `public/p/<ID>/img/<품종키>.jpg`로 넣는다 (정사각 크롭 권장, 600~900px).
3. `node tools/order-proposal/build.js tools/order-proposal/proposals/<ID>.json`
4. 커밋·배포 후 `https://open-garden.co.kr/p/<ID>/` 를 고객 카톡방에 보낸다.

마감된 제안서는 폴더째 지우면 링크가 404가 된다.
