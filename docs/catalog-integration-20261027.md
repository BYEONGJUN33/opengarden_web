# 카탈로그 통합 검증 (2026-10-27)

공개 웹사이트 실제 저장소의 기존 사진 갤러리에 기능을 통합했습니다. 원본 ZIP은 현재 대화 첨부에 없으므로 기존 코드를 기준으로 구현했으며 ZIP을 복원했다고 주장하지 않습니다.

- `/api/catalog`: 기존 필드 ID 화이트리스트와 규격 미확정 제외를 유지. 원본 첨부 URL 대신 동일 출처 이미지 API 주소 반환.
- `/api/plant-image`: 등록된 공개 카탈로그 레코드만 조회. Airtable 첨부 호스트만 허용하고 리디렉션·10MB 초과·비이미지를 차단. 최대 1000px WebP에 저장소 로고를 실제 합성. 이미지 처리를 위해 sharp와 npm 잠금 파일 추가.
- `/plants/:group/:id`: 서버에서 HTML·canonical·OG·JSON-LD 제공. 가격/재고를 만들어내지 않음. `/sitemap-plants.xml`과 robots 연결. 기존 정적 사이트맵 유지.
- 검색: 국명·학명·규격·SKU, 공백/대소문자 정규화, 검색 색인 미리 생성, 120ms 입력 지연.
- 직원용 ERP: 공개 품목 정보만 v1 base64url로 전달. 최대 20개/7000자, 연락처/가격 제외. 공식 도메인은 기존 ERP 운영 주소, 테스트 호스트는 고정 ERP Preview로 연결. 자동 저장/발행하지 않음.
- API 실패 시 샘플 상품을 실상품처럼 보여주지 않으며 저장된 담기 목록을 유지.

## 검증 범위

Node 기본 테스트 러너로 검색, 전달 형식, 가격 비노출, 페이지네이션, 사진 URL 비노출, HTML/JSON-LD 이스케이프, 이미지 호스트/크기 제한, 워터마크 픽셀, 전체 인라인 JS 문법을 검사합니다. 테스트는 가짜 Airtable 응답만 사용합니다.
로컬 브라우저 모의 데이터에서 규격 통합 카드, 복합 검색, 사진 넘김과 로고 표시를 확인했습니다.

## 연동과 제한

ERP 별도 PR의 `catalog-selection.js`는 웹사이트 Preview 이미지 주소를 허용합니다. 기존 feature 브랜치의 제안서 가져오기는 공식 도메인의 사진만 허용하므로 두 PR을 함께 검토해야 합니다. 식물 고유번호 필드의 새 매핑을 추정하지 않았으며 공개 레코드 ID를 전달합니다. 기존 사진 첨부와 라인업 테이블을 그대로 읽습니다.

원본 사진을 다른 경로에서 공개하면 이 API가 그 경로까지 보호하지는 않습니다. SEO 코드는 PR 상태이며 운영 노출/검색 등록 완료를 의미하지 않습니다. Production/main 병합·배포, OAuth 환경변수 변경, Airtable 쓰기는 수행하지 않습니다.
