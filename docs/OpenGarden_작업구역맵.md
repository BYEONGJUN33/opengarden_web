# OpenGarden 작업 구역 맵 (2026-07-13 기준)

> "어떤 작업을 어디서 하고, 연동은 어디서 이어지는가" 한 장 정리.
> 원본: 에어테이블 채팅의 설계도(4단계 로드맵) + 이 채팅의 아키텍처 문서 → 현재 진행 상황 반영 통합판.

---

## 1. 작업 구역 (채팅방·도구별 담당)

| 구역 | 담당 작업 | 현재 상태 |
| --- | --- | --- |
| 💬 **채팅① 에어테이블 자동화** | **1단계 제안서 자동화**: Settings·환율·원화_원가 → 제안서/제안서항목 테이블 → 마진 적용 → PDF 템플릿 | 환율 lookup까지 진행, 제안서 테이블·PDF 남음 |
| 💬 **채팅② 웹 제작 (이 채팅)** | **2단계 홈페이지 설계**: 틀 2페이지 + 백엔드 함수 + 문서 일체 | ✅ 설계 완료 — 이후엔 상담·문서 갱신 창구 |
| 💻 **클로드 코드 (노트북)** | **2단계 실행**: git/GitHub → 로컬 미리보기 → 에어테이블 연동 → Vercel 배포 → 카페24 DNS 연결 | 세팅 완료, 로컬 미리보기 단계 |
| 🎨 **클로드 디자인** | 모션·비주얼 다듬기 (페이드인 등) | 배포 전 아무 때나, 대기 |
| 👤 **직접 할 일 (계정 필요)** | 에어테이블 토큰 발급·견적요청 테이블 생성, GitHub 가입, 카톡 채널 주소, 사진·수치·사업자 정보, Hostinger 플랜 확인 | 진행하면서 각 시점에 |

## 2. 연동 접점 — 두 흐름이 만나는 곳 ⭐

```
[웹 카탈로그] --담기·견적 요청--> [견적요청 테이블] <--품목 연결-- [제안서 자동화]
     (클로드 코드에서 연동)         (에어테이블)          (채팅①에서 연결)
```

- **견적요청 테이블**이 핵심 교차점: 웹의 POST /api/quote가 여기 기록하고(요청번호 발급),
  제안서 자동화가 이 기록을 받아 제안서 → PDF 발송으로 잇는다 = **3단계 완성 조건**
- 웹 쪽 배선은 **클로드 코드**에서, 에어테이블 쪽 연결(견적요청 ↔ 제안서 테이블)은 **채팅①**에서 진행
- 원칙: 마진은 Master DB가 아닌 **제안서 단계**에서 적용 (Master DB = 환율 반영된 순수 원가만)

## 3. 전체 로드맵 현황 (4단계)

| 단계 | 내용 | 상태 | 구역 |
| --- | --- | --- | --- |
| 1단계 | 제안서/견적서 자동 생성 | 🔄 진행 중 (환율까지, 제안서 테이블·PDF 남음) | 채팅① |
| 2단계 | 홈페이지 + 카탈로그 | 🔄 설계 완료 → 배포·연동 진행 중 | 이 채팅(설계) + 클로드 코드(실행) |
| 3단계 | SNS·카톡 견적 연동 | ⏸ 대기 — 견적요청 테이블이 생기면 시작 가능 | 채팅① + 클로드 코드 |
| 4단계 | 데이터 DB 고도화·백업 | ⏸ 장기 (에어테이블 주기 백업은 남은 작업에 추가됨) | 추후 |

## 4. 확정된 인프라 결정사항

- 배포: **Vercel 1차** (코드 무변환·기존 사이트와 분리) → vercel.app 검수 → 카페24 DNS에서 open-garden.co.kr 연결 (서브도메인 테스트 옵션)
- 기존 Hostinger 워드프레스는 전환 순간까지 유지 (되돌리기 가능)
- Hostinger가 Business 플랜 이상이면 추후 통합 이전 옵션 열려 있음 (대표님 플랜 확인 중)
- 데이터 원본은 에어테이블 단일화, 가격은 서버에서 차단, 토큰은 환경변수만

## 5. 바로 다음 할 일 (구역별 한 줄)

- 클로드 코드: 로컬 미리보기 확인 → GitHub 푸시 → 견적요청 테이블 생성 안내 받기
- 채팅①: 제안서/제안서항목 테이블 생성 이어가기 (환율 다음 단계)
- 직접: 대표님께 Hostinger 플랜 + 도메인 사용 현황 확인, 사진·수치 수집 시작
