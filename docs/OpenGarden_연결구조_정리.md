# OpenGarden 연결 구조 정리 (웹 ↔ 카톡 ↔ 에어테이블)

> 지금까지 채팅에서 결정된 연결 구조를 한 장으로 정리. 2026-07-17 기준.

---

## 1. 3계층 구조 (한눈에)

```
[사용자]  ─ 카톡 / 인스타 / 스마트스토어 / 검색 으로 유입
   │
   ▼
① 프론트 (public/)          사용자가 보는 화면. 데이터 없음, 화면만.
   index.html    홈 원페이지 (소개·서비스·사례·이용안내·FAQ)
   catalog.html  카탈로그: 검색·필터 → 담기 → 견적 모달
   │  ▲
   │  │ fetch()
   ▼  │
② 백엔드 (api/)             함수 2개. 토큰 보관, 가격 차단, 기록 담당.
   GET  /api/catalog   품종 목록 읽기 (가격 제거 후 전달, 10분 캐시)
   POST /api/quote     견적 요청 기록 + 요청번호 발급
   │  ▲
   │  │ Airtable REST API (토큰=환경변수)
   ▼  │
③ 데이터 (Airtable)         유일한 원본. 여기서만 수정.
   Master DB (1,924종)  ← 카탈로그가 읽음 (View 2개: 즉시출하 / 사전예약)
   견적요청 테이블       ← 견적 요청이 쌓임
   제안서 테이블         ← 채팅①에서 구축 중, 견적요청과 연결 예정
```

**핵심 원칙 3개**
1. 가격(단가_EUR·원화)은 `api/catalog.js`의 필드 화이트리스트에서 제외 → 브라우저에 애초에 도달하지 않음
2. 에어테이블 토큰은 호스팅 환경변수에만 (프론트·코드·깃에 절대 없음)
3. 데이터는 HTML에 하드코딩 금지 → 에어테이블에서 고치면 사이트에 자동 반영 (10분 내)

## 2. 견적 플로우 (웹 → 카톡 → 에어테이블) ⭐

```
카탈로그에서 품종 담기  (하단 바에 "N종 선택됨")
        │
        ▼  [견적 요청하기] → 모달에서 수량·성함·요청사항 입력
        │
        ▼  [목록 복사하고 카카오톡 열기] 클릭 시 3가지가 순서대로 실행:
        │
   ① POST /api/quote  ──→  견적요청 테이블에 레코드 생성
   │                        요청번호 발급 (Q-20260717-A3F)
   │
   ② 목록 텍스트를 클립보드에 복사
   │     [오픈가든 견적 요청 · Q-20260717-A3F]
   │     요청자: 홍길동 / ○○조경
   │     1. 품종A · P9 · 10개
   │     2. 품종B · C2 · 5개
   │     요청사항: ...
   │     (복사 실패 시 → 수동 복사 상자 표시)
   │
   ③ 카카오톡 채널 채팅 열림 → 사용자가 붙여넣기
        │
        ▼
   담당자가 카톡 수신 → 요청번호로 에어테이블 기록 매칭
        │
        ▼
   제안서 작성 → PDF 발송 → 계약 → 납품
```

**왜 이렇게 설계했나 (기술 제약)**
- 카카오톡 채널 링크(pf.kakao.com)는 **메시지를 미리 채워서 열 수 없음** → "기록 + 복사 + 열기" 3단 구조로 우회
- 완전 자동 전달(상담톡 API)은 비즈니스 심사·비용 필요 → 2차 단계로 보류
- **안전망**: 사용자가 카톡에서 붙여넣기를 안 하고 이탈해도 ①에서 이미 기록됨 → 문의 유실 없음
- **요청번호**가 카톡 대화 ↔ 에어테이블 기록을 잇는 열쇠

## 3. 카탈로그 표시 플로우 (에어테이블 → 웹)

```
Master DB
  └ View: 즉시 출하 가능 카탈로그  ─┐
  └ View: 사전 예약용 카탈로그    ─┤
                                   ▼
              GET /api/catalog?group=immediate|preorder
                                   │  · 필드 화이트리스트로 가격 제외
                                   │  · 재고는 수량 대신 유무(있음/없음)만
                                   │  · 100건씩 페이지네이션 → 전부 수집
                                   │  · 10분 캐시 (API 한도 보호)
                                   ▼
              catalog.html 카드 그리드
                사진 / 국명 / 학명 / 규격·Zone·카테고리 태그
                필터: 카테고리(데이터에서 자동 생성) · 내한성 · 공급구분
```

**표시 필드 매핑**
| 에어테이블 | 사이트 |
| --- | --- |
| 국명 | 카드 메인 이름 |
| 학명 | 카드 서브 (이탤릭) |
| Size (규격) | 태그 (P9, C2 등) |
| 카테고리 | 필터 칩 + 태그 |
| 내한성 | 필터 + 태그 (Zone 4–9) |
| Status | 배지 (즉시 출하 / 사전 예약) |
| 이미지_URL | 카드 사진 ⚠️ 고정 URL만 (첨부 URL은 만료됨) |
| 재고 | 유무만 (수량 비노출) |
| 단가_EUR / 원화 | ❌ 전달 안 함 |

## 4. 채널별 역할

| 채널 | 역할 | 연결 |
| --- | --- | --- |
| **홈페이지** | 소개 + 카탈로그 + 견적 접수 허브 | 모든 채널의 목적지 |
| **카카오톡 채널** | 상담·견적 접수 창구 (주 유입) | 사이트 CTA → 카톡 / 카톡 → 사이트 링크 |
| **인스타그램** | 유입 | 프로필 링크 → 사이트 |
| **네이버 스마트스토어** | 소매 판매 (B2B 견적과 분리) | 푸터 링크 |
| **에어테이블** | 데이터 원본 + 제안서 자동화 | 사이트·제안서 양쪽이 참조 |

## 5. 인프라 구조

```
도메인: open-garden.co.kr (카페24 구매·DNS 관리)
   │
   ├─ 현재: Hostinger 워드프레스 (전환 전까지 유지)
   └─ 전환 후: Vercel (정적 + 함수) ← 새 홈페이지
                 환경변수: AIRTABLE_TOKEN / BASE_ID / TABLE_ID / VIEW×2 / QUOTE_TABLE
```

배포 순서: Vercel 배포 → `xxx.vercel.app`으로 검수 → (선택) 서브도메인 테스트 → 카페24 DNS를 Vercel로 변경 → 완료
※ 도메인 이전이 아니라 DNS 변경이라 비용 없음, 기존 사이트는 전환 순간까지 살아있음

## 6. 두 흐름이 만나는 지점 ⭐

```
[웹 견적 요청] ──기록──> [견적요청 테이블] <──연결── [제안서 자동화 (채팅①)]
                              │
                              └─ 상태: 신규 → 제안서발송 → 계약 → 종료
```

- 웹 쪽 배선(POST /api/quote): **클로드 코드**에서 배포 시 활성화
- 에어테이블 쪽 연결(견적요청 ↔ 제안서 테이블): **채팅① (에어테이블 자동화)**에서 진행
- 둘이 이어지면 = **3단계 완성** (요청 → 제안서 → 발송이 한 흐름)
- 원칙: 마진은 Master DB가 아닌 **제안서 단계**에서 적용

## 7. 파일 구조 (v5 기준)

```
opengarden-starter/
├─ CLAUDE.md              ← 클로드 코드가 읽는 규칙서 (절대 원칙 5개)
├─ README.md              ← 셋업·배포 순서
├─ package.json
├─ public/
│  ├─ index.html          홈 원페이지 (10개 섹션)
│  ├─ catalog.html        카탈로그 + 견적 플로우
│  ├─ privacy.html        개인정보 처리방침 (틀)
│  ├─ 404.html
│  ├─ robots.txt / sitemap.xml
│  └─ assets/  logo.svg · og.jpg (카톡 공유 미리보기)
├─ api/
│  ├─ catalog.js          GET  /api/catalog
│  └─ quote.js            POST /api/quote
└─ docs/                  아키텍처 · 프로젝트구조 · 인수인계 · 유저플로우
```
