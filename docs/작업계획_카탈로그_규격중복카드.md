# 카탈로그 — 같은 품종이 규격별로 카드가 갈라지는 문제

작성 2026-08-14 · 대상 `src/catalog.html`
보고: 병준 주임 (2026-08-14, 프로덕션 확인 중 발견)

---

## 1. 재현 및 규모 (전수 실측)

| | 레코드 | 고유 품종 | 초과 카드 |
|---|---|---|---|
| 국내 라인업 | 56 | 49 | **7** |
| 판매 라인업 | 241 | **101** | **140** |
| 합계 | 297 | **150** | **147 (49%)** |

**카탈로그 카드의 절반이 같은 품종의 규격 변형입니다.**

대표 사례 — 히아신스 '델프트 블루' 한 품종이 카드 6장:

| 규격 | SKU |
|---|---|
| 14/15 | HBM-HYA-001-1415 |
| 15/16 | HBM-HYA-001-1516 |
| 16/17 | HBM-HYA-001-1617 |
| 17/18 | HBM-HYA-001-1718 |
| 18/19 | HBM-HYA-001-1819 |
| 19/+ | HBM-HYA-001-19P |

히아신스는 대부분 품종이 5~6개 규격을 가집니다. 판매 라인업 **51종이 이 상태**입니다.

### 언제부터 있었나
**이번 배포로 생긴 문제가 아닙니다.** 카탈로그는 처음부터 에어테이블 레코드 1건 = 카드 1장이었고,
사진 갤러리·2단 분류 작업은 이 매핑을 건드리지 않았습니다.
다만 2단 분류로 `히아신스(83)`를 눌러 한 화면에서 보게 되면서 눈에 띄게 된 것으로 보입니다.
→ **롤백 불필요.**

---

## 2. 사실은 문제가 두 개입니다

### 문제 A — 규격 분할 (코드로 해결)
같은 품종·다른 규격이 별도 레코드. 판매 51종 + 국내 2종.
에어테이블 구조상 규격별 SKU·단가가 달라야 하므로 **레코드 분리 자체는 옳습니다.**
잘못된 건 그걸 그대로 카드로 펼치는 화면 쪽입니다.

### 문제 B — 진짜 중복 데이터 (에어테이블에서 정리 필요)
코드로는 못 고칩니다.

| 품종 | 상태 |
|---|---|
| 화백 '파이어칩' | **5치 규격 3건이 완전 동일** — 중복 입력으로 보임 |
| 에키네시아 'ㅇ' | 국명이 `ㅇ`, 학명 없음, 규격 `확인필요` 1건 + `5치` 2건 |

> 문제 A를 고쳐도 이 둘은 남습니다. 화백은 "5치 / 5치 / 5치"로 묶이고,
> 에키네시아는 이름이 `ㅇ`인 카드가 그대로 노출됩니다.

## 3. 수정 방향

### 3-1. 묶는 기준
`국명 + 학명`을 키로 묶습니다. (SKU 앞자리는 라인업마다 규칙이 달라 부적합)
학명이 비어 있으면 국명만 사용.

### 3-2. 화면
- **카드 = 품종 1장.** 메타에 `규격 6종` 표시
- **규격 선택은 상세 모달에서.** 규격 칩을 누르면 해당 레코드의 사진·SKU·최소주문수량으로 전환
- 규격이 하나뿐인 품종(대다수의 국내 품목)은 지금과 동일하게 동작

### 3-3. 견적 담기 — 여기가 핵심
현재 장바구니는 `{레코드ID: 수량}`이고, 견적 전송 시
`{sku, kname, size, qty}`를 보냅니다 (`catalog.html:699`).

**규격별 SKU가 견적의 핵심 정보이므로 절대 뭉개면 안 됩니다.**

→ 장바구니 키는 **지금처럼 레코드ID를 유지**합니다.
   같은 품종의 다른 규격 2개를 담으면 견적 목록에 2줄로 뜹니다. 이게 맞는 동작입니다.
→ 카드의 '견적에 담기' 버튼은, 규격이 여러 개면 **바로 담지 않고 상세 모달을 엽니다.**
   규격을 안 고르고 담으면 어느 SKU인지 알 수 없습니다.

### 3-4. 대표 사진·정렬
- 대표 사진: 그룹 내에서 **사진이 가장 많은 레코드**의 첫 장
- 규격 정렬: 숫자를 뽑아 오름차순 (`14/15` → `15/16` → … → `19/+`)
  현재 에어테이블 선택지 순서는 뒤죽박죽이라 그대로 쓰면 안 됩니다
- 갤러리: 선택된 규격의 사진만 표시

### 3-5. 부수 영향
- 카드 수 **297 → 150**. 상단 문구가 "150개 품종 표시 중"으로 바뀜
- 2단 분류 건수도 전부 바뀜 (히아신스 83 → 17 등)
- 공유 링크 `?item=<레코드ID>` — 기존 링크가 깨지지 않도록
  레코드ID로 들어오면 그 품종을 열고 해당 규격을 선택된 상태로 표시

## 4. 결정이 필요한 것

1. **문제 B 데이터 정리** — 화백 '파이어칩' 중복 3건, 에키네시아 'ㅇ' 3건.
   누가 언제 정리할지. (코드 수정과 무관하게 남는 문제)
2. **카드에 규격을 몇 개까지 노출할지** — 메타에 `규격 6종`만 쓸지,
   `14/15 외 5종`처럼 첫 규격을 같이 보여줄지
3. **국내 라인업 규격 필드가 `multipleSelects`** — 한 레코드가 이미 여러 규격을 담을 수 있습니다.
   이 경우 규격 칩을 어떻게 뽑을지 (현재 데이터엔 복수 선택된 레코드가 없어 당장은 무관)
