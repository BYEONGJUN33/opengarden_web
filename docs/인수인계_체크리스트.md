# 오픈가든 웹사이트 — 인수인계 체크리스트

> 담당자 퇴사에 따라 모든 계정·소유권을 대표 계정으로 넘기는 절차.
> **순서를 지켜야 사이트가 멈추지 않습니다.** 2026-10-25 작성.

---

## 왜 순서가 중요한가

사이트는 담당자 개인 계정으로 발급한 **토큰**에 의존합니다.
담당자 계정이 사라지면 토큰이 먼저 죽고, 그 즉시 아래 기능이 멈춥니다.

| 토큰이 죽으면 | 멈추는 기능 |
|---|---|
| `AIRTABLE_TOKEN` | **카탈로그 전체** · 견적 접수 · 재고조정앱 |
| `SOLAPI_*` (4개) | 견적 접수 **알림톡 발송** (접수 자체는 계속 동작) |

그래서 **소유권을 넘기기 전에, 대표 계정으로 발급한 새 토큰으로 먼저 갈아끼웁니다.**
이렇게 하면 담당자 계정을 지워도 사이트는 멀쩡합니다.

```
1단계  대표 계정 개설        →  2단계  새 토큰으로 교체(사이트는 이미 대표 자원으로 동작)
   →  3단계  소유권 이전     →  4단계  담당자 계정 제거
```

## 1단계 · 대표 계정 개설 (대표님이 하실 일)

| 서비스 | 주소 | 비고 |
|---|---|---|
| GitHub | github.com | 저장소 이전 받을 계정 |
| Vercel | vercel.com | **GitHub 계정으로 로그인** 권장 |
| 에어테이블 | airtable.com | |
| 솔라피 | solapi.com | 알림톡 발송. 사업자 정보 필요 |

## 2단계 · 토큰 교체 (담당자 재직 중에 끝내야 함) ⚠ 가장 중요

### 2-1. 에어테이블

1. 담당자가 대표님을 **베이스 소유자(Owner)** 로 초대 (베이스 우상단 Share)
2. **대표님 계정에서** 개인 액세스 토큰 발급
   - airtable.com/create/tokens → Create new token
   - Scopes: `data.records:read`, `data.records:write`
   - Access: **OpenGarden 베이스만** 선택 (전체 워크스페이스 ✗)
3. Vercel → 프로젝트 → Settings → Environment Variables → `AIRTABLE_TOKEN` 값을 새 토큰으로 교체
4. **Redeploy** 후 카탈로그가 뜨는지 확인

> 기존 토큰은 개발 중 대화에 노출된 이력이 있어, 어차피 정식 오픈 전 재발급 대상이었습니다.
> 이번에 교체하면 그 건도 함께 해결됩니다.

### 2-2. 솔라피

1. 대표님 계정에서 API 키 발급 (콘솔 → 개발/연동 → API Key)
2. 카카오 알림톡 **채널·템플릿을 대표님 계정으로 등록** (채널 연동 → 템플릿 심사)
3. Vercel 환경변수 교체: `SOLAPI_API_KEY` `SOLAPI_API_SECRET` `SOLAPI_PFID` `SOLAPI_TEMPLATE_ID` (`SOLAPI_SENDER`는 선택)
4. 카탈로그에서 견적을 한 건 넣어 알림톡이 오는지 확인

> 템플릿 심사에 영업일 기준 1~3일 걸립니다. **가장 먼저 시작하세요.**

### 2-3. 나머지 환경변수

아래는 토큰이 아니라 식별자라 그대로 두면 됩니다.

```
AIRTABLE_BASE_ID  AIRTABLE_TABLE_DOMESTIC  AIRTABLE_TABLE_IMPORT
AIRTABLE_QUOTE_TABLE  AIRTABLE_STOCK_TABLE  AIRTABLE_WORKER_TABLE
AIRTABLE_GROUP_TABLE  STOCK_FARMS
```

**교체 전에 Vercel 환경변수 전체를 복사해 따로 보관해두세요.** 되돌릴 때 필요합니다.

## 3단계 · 소유권 이전

### 3-1. Vercel 프로젝트

Vercel 공식 절차로 **무중단 이전**이 됩니다.

> 조건: 이전하는 쪽은 **Owner**, 받는 쪽 팀의 **멤버**여야 합니다.

**방법 A — 프로젝트 이전 (권장, 단 대표님 Pro 팀 필요)**
1. 대표님이 Vercel **Team** 생성 후 담당자를 멤버로 초대
2. 담당자: 프로젝트 → Settings → General → 맨 아래 **Transfer Project** → 대표님 팀 선택
3. 넘어가는 것: 배포 이력 · **환경변수** · **도메인** · Git 연동 · 보안 설정 · 크론
4. **안 넘어가는 것: 통합(Integrations)** → 이전 후 다시 연결해야 합니다
5. 받는 팀에 **결제수단이 등록돼 있어야** 합니다

**방법 B — 계정 자체를 넘기기 (무료, Hobby일 때)**
Vercel 무료(Hobby) 플랜은 팀원 초대가 안 돼 방법 A를 쓸 수 없습니다.
이때는 담당자 Vercel 계정의 **이메일을 대표님 이메일로 변경**해 계정째 넘깁니다.
(Settings → General → Email). 로그인 수단도 함께 바꿔야 합니다.

> Vercel 무료 플랜은 **비상업적·개인 용도만** 허용됩니다. 상업 사이트이므로
> 어느 쪽이든 Pro 전환을 검토하시는 게 안전합니다.

### 3-2. GitHub 저장소

1. 저장소 → Settings → General → 맨 아래 **Transfer ownership** → 대표님 계정
2. 이전 후 **Vercel 연동이 끊길 수 있습니다.** 반드시 확인:
   - Vercel → 프로젝트 → Settings → Git → 저장소가 올바로 연결돼 있는지
   - 끊겼으면 **Connect Git Repository**로 다시 연결
   - 대표님 계정에 **Vercel GitHub App 설치**가 필요할 수 있습니다
3. 아무 문구나 한 줄 고쳐 커밋 → 1~2분 뒤 사이트에 반영되는지로 확인

> **Vercel 이전을 먼저, GitHub 이전을 나중에** 하시면 연동 복구가 한 번으로 끝납니다.

### 3-3. 에어테이블

- 베이스가 속한 **워크스페이스 소유자**를 대표님으로 변경
  (워크스페이스 설정 → Members → 대표님을 Owner로 → 담당자 제거)
- 베이스만 공유하면 담당자 계정 삭제 시 워크스페이스째 사라질 수 있습니다

### 3-4. 도메인 (open-garden.co.kr)

현재 A 레코드가 Vercel(`216.198.79.1`)을 가리키고 있습니다.
도메인 자체는 **국내 등록기관(가비아·후이즈·카페24 등)** 에 있습니다.

1. 어느 기관에 등록돼 있는지 확인 (whois.kr 조회)
2. 해당 기관에서 **등록인(소유자) 정보 변경** 신청
   - 보통 사업자등록증·대표자 신분증 등 서류가 필요합니다
   - 기관마다 양식이 달라 고객센터 문의가 빠릅니다
3. 결제수단·자동갱신을 대표님 것으로 변경 **(갱신 실패 시 도메인이 만료됩니다)**

> DNS 설정은 건드리지 마세요. 소유자만 바뀌면 사이트는 그대로 동작합니다.

### 3-5. 카카오톡 채널

- 채널명: `pf.kakao.com/_lGfxhX`
- 카카오 비즈니스 채널 관리자센터 → 관리자 권한에 대표님 추가 → **마스터 권한 양도** → 담당자 제거

### 3-6. 네이버 서치어드바이저

사이트 소유확인이 담당자 계정에 묶여 있습니다.

```html
src/index.html
<meta name="naver-site-verification" content="a298...43e9" />
```

1. 대표님 계정으로 searchadvisor.naver.com에서 사이트 등록
2. 발급된 새 인증 코드로 위 줄의 `content` 값을 교체 후 커밋
3. 네이버에서 소유확인 완료
4. 담당자 계정에서는 사이트 삭제

## 0단계 · 환경변수 값 확보 ⚠ 먼저 확인할 것

Vercel은 Production 환경변수를 기본적으로 **Secret**으로 저장합니다.
**Secret으로 저장된 값은 대시보드에서도 CLI에서도 다시 읽을 수 없습니다.**

지금 바로 확인하세요. 옛 프로젝트에서:

```bash
npm i -g vercel
vercel login
vercel link              # 옛 프로젝트 선택
vercel env ls            # Type 열이 Config인지 Secret인지 확인
vercel env pull .env.backup --environment=production
```

`.env.backup`을 열어 **값이 실제로 들어있는지, 자리표시자인지** 확인하세요.

| 결과 | 조치 |
|---|---|
| 실제 값이 있다 | 그대로 새 프로젝트에 입력 |
| 자리표시자(Secret) | **원본 서비스에서 재발급** — 에어테이블 토큰 페이지, 솔라피 콘솔 |

> `.env.backup`에는 토큰이 평문으로 들어있습니다. 작업이 끝나면 **반드시 삭제**하세요.
> 저장소에 커밋되지 않도록 주의하세요(`.gitignore`에 `.env*`가 있는지 확인).

## 3단계 · 새 프로젝트에 환경변수 입력

**실제로 넣어야 할 것은 6개뿐입니다.** 나머지는 코드에 기본값이 박혀 있어 설정하지 않아도 됩니다.
(`api/*.js`에서 `process.env.X || '기본값'` 형태로 처리)

### 반드시 넣어야 하는 것 — 2개

없으면 `/api/catalog`이 500을 반환하고 **카탈로그·견적·재고앱이 전부 멈춥니다.**

| 변수 | 값 |
|---|---|
| `AIRTABLE_TOKEN` | 에어테이블 개인 액세스 토큰 — **계정별로 발급** (아래 주의) |
| `AIRTABLE_BASE_ID` | `appzLstFHtHcQlWSu` |

### 알림톡을 쓰려면 — 4개

하나라도 빠지면 **알림톡만 조용히 꺼집니다.** 견적 접수 자체는 정상 동작하고
고객에게는 요청번호가 그대로 표시됩니다. 즉 사이트가 깨지지는 않습니다.

| 변수 | 값 출처 |
|---|---|
| `SOLAPI_API_KEY` | 솔라피 콘솔 → 개발/연동 → API Key |
| `SOLAPI_API_SECRET` | 〃 |
| `SOLAPI_PFID` | 솔라피에 연동한 카카오 채널 ID |
| `SOLAPI_TEMPLATE_ID` | 심사 승인된 알림톡 템플릿 ID |

### 선택 — 1개

| 변수 | 비고 |
|---|---|
| `SOLAPI_SENDER` | 발신번호. **없어도 알림톡은 정상 발송**되고, SMS 대체발송만 꺼집니다. 현재 미설정 |

### 넣지 않아도 되는 것 — 7개 (코드 기본값)

```
AIRTABLE_TABLE_DOMESTIC  → tblDMLlaBwkW1NfhU   (국내 라인업)
AIRTABLE_TABLE_IMPORT    → tblylbZq6PLfzH1Ol   (판매 라인업)
AIRTABLE_GROUP_TABLE     → tbl7iGQoFTeGUTXyd   (분류)
AIRTABLE_QUOTE_TABLE     → 견적요청
AIRTABLE_STOCK_TABLE     → 재고
AIRTABLE_WORKER_TABLE    → 작업자
STOCK_FARMS              → 1농장…
```

테이블을 새로 만들거나 이름을 바꾼 게 아니라면 **건드리지 마세요.**

### 적용 환경

현재 운영 프로젝트의 설정을 그대로 따르면 됩니다.

| 변수 | 환경 |
|---|---|
| `AIRTABLE_TOKEN` · `AIRTABLE_BASE_ID` | Production + Preview |
| `SOLAPI_*` | Production |

> Preview(미리보기 배포)에서도 카탈로그를 확인하려면 에어테이블 2개는 Preview에도 필요합니다.
> 솔라피를 Production에만 두면 **미리보기에서 테스트할 때 실제 알림톡이 나가지 않습니다.** 의도된 설정입니다.

## ⚠ 에어테이블 토큰은 계정별입니다

**같은 베이스라도 토큰은 발급한 사람 계정에 묶입니다.** 베이스가 회사 워크스페이스에
있는 것과는 별개입니다. 담당자 계정이 워크스페이스에서 빠지면 그 토큰은 즉시 무효가 됩니다.

그래서 **대표님(또는 회사 공용) 계정에서 새로 발급해야 합니다.**

1. 대표님 계정이 OpenGarden 베이스에 접근 권한이 있는지 먼저 확인
2. airtable.com/create/tokens → **Create new token**
3. Scopes: `data.records:read`, `data.records:write`
4. Access: **OpenGarden 베이스만** 선택 (워크스페이스 전체 ✗)
5. 발급된 값을 새 Vercel 프로젝트의 `AIRTABLE_TOKEN`에 입력

> 옛 토큰은 개발 중 대화에 노출된 이력이 있어 어차피 교체 대상이었습니다.
> 이번에 새로 발급하면 그 건도 함께 정리됩니다.

## 솔라피는 계정을 넘기면 값 그대로

솔라피 **계정 자체를 인계**하시면 `SOLAPI_API_KEY`·`SOLAPI_API_SECRET`은
기존 값을 그대로 쓰시면 됩니다. 새로 발급할 필요 없습니다.

## 5단계 · 도메인 연결 (open-garden.co.kr)

현재 상태: 국내 등록기관의 **A 레코드**가 Vercel을 가리키고 있습니다.
**DNS를 갈아엎을 필요는 없습니다.** 어느 Vercel 프로젝트가 이 도메인을 쓰는지만 바꾸면 됩니다.

### 방법 A — 무중단 (권장)

1. 새 프로젝트 → Settings → **Domains** → **Add Domain** → `open-garden.co.kr`
2. 다른 Vercel 계정이 쓰는 중이라 **"Verify domain access"** 가 뜹니다
3. Vercel이 보여주는 **TXT 레코드**를 등록기관 DNS에 추가
   - 이름: `_vercel`
   - 값: Vercel이 준 문자열
4. 전파 후 Vercel이 자동 인증 → 도메인이 새 프로젝트로 붙습니다
5. Vercel이 **A 레코드 값**을 보여주면 현재 값(`216.198.79.1`)과 비교해
   다르면 등록기관에서 교체하세요
6. `www.open-garden.co.kr`도 쓰신다면 같이 추가

### 방법 B — 간단하지만 수 분 끊김

1. **옛 프로젝트**에서 도메인 제거
2. 새 프로젝트에 즉시 추가
3. 제거~추가 사이에 사이트가 안 열립니다

> 영업 시간에는 방법 A를, 급하면 방법 B를 쓰시되 **심야에** 하세요.
